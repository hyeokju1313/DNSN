## 1. 배경

### 1.1 예지보전과 C-MAPSS

- 잔여수명 예측은 정비 시점을 정하는 데 쓰인다. 너무 늦게 예측하면 고장이 나고, 너무 일찍 예측하면 멀쩡한 부품을 교체한다.
- C-MAPSS는 NASA가 엔진 시뮬레이터로 만든 고장까지의 기록이다(Saxena 등 2008). 잔여수명 예측 연구에서 가장 널리 쓰는 기준 데이터다.
- FD001의 학습용 엔진은 100대뿐이다. 모델이 크면 과적합이 실제 문제가 된다.

### 1.2 커넥톰을 저장소로 쓴 선행 연구

| 연구 | 한 일 | 결과 | 남은 빈틈 |
|---|---|---|---|
| Costi 등 2025, Biomimetics | 암컷 초파리 뇌(FlyWire)에서 가장 많이 연결된 뉴런 50~1,500개와 전체(104,909개)를 저장소로 사용 | 무작위 저장소보다 과적합이 적음. 가중치만 섞으면 이점이 사라짐 | 인공 3체 문제 하나로만 시험. 실제 산업 데이터와 수컷 CNS(뇌+신경삭)는 시험하지 않음 |
| Guragain 등 2026, arXiv | 여러 종의 부위 단위 커넥톰(초파리는 49개 노드)을 저장소로 사용 | 같은 배선에 무작위 가중치를 넣으면 성능이 떨어짐. 생물 가중치가 필요하다고 결론 | 뉴런 단위 커넥톰이 아님 |
| Churchland 등 2026, arXiv | 선충 커넥톰 저장소에서 배선, 부호, 가중치 크기, 가중치 배치를 하나씩 바꿔 봄 | 성능과 강건성의 차이가 spectral radius와 전체 배율에 크게 좌우됨 | 이점이 정확한 배선에서 오는지 분포에서 오는지 가려야 함 |

이 프로젝트는 Costi 등의 결과가 **실제 산업 데이터**와 **수컷 초파리 전체 CNS**에서도 성립하는지 시험하고, Churchland 등이 제기한 문제를 대조군으로 가린다.

### 1.3 수컷 초파리 CNS 커넥톰

- Janelia, Google, 케임브리지 공동팀이 2026-09-03 Cell에 발표했다. 뇌와 신경삭(VNC)이 목으로 이어진 상태로 재구성한 첫 전체 중추신경계 연결도다. CC-BY 4.0으로 공개돼 있다.
- 신경삭에는 몸의 감각 뉴런과 운동 뉴런이 있다. 그래서 엔진 센서를 몸의 감각 뉴런에 넣고 운동 뉴런에서 답을 읽는, 감각에서 운동까지 이어지는 전체 경로를 쓸 수 있다.

## 2. 문제 정의와 가설

**문제 문장**: 수컷 초파리 전체 CNS 배선을 순환 신경망 구조로 쓰면, 학습 엔진이 적을 때 무작위 배선 망이나 LSTM보다 잔여수명을 더 안정적으로 예측하는지 검증한다.

| 가설 | 내용 | 검증 |
|---|---|---|
| H1 | 학습 엔진이 적을 때(10~25대) 커넥톰 저장소는 같은 크기의 무작위 저장소보다 과적합 격차가 작다 | 6.3 데이터 양 실험 |
| H2 | 그 차이는 연결 수를 유지한 채 배선만 섞으면 줄어든다. 줄지 않으면 이점은 연결 수 분포에서 온 것이다 | 6.2 대조군 |
| H3 | 전체 CNS가 부분 커넥톰(가장 많이 연결된 N개, 중심복합체, 버섯체)보다 낫다 | 5.5 부분 커넥톰 비교 |
| H4 | 세포 유형별 값을 학습하면(M2) LSTM과의 격차가 줄어든다 | 6.1 비교 모델 |

가설이 기각돼도 결과로 인정된다. 수업의 성공 기준이 "왜 실패했고, 무엇을 바꾸었고, 결과가 어떻게 달라졌는지"를 설명하는 것이기 때문이다. 최고 성능(SOTA) 경쟁은 목표가 아니다.

연구마다 규약이 달라 수치를 직접 비교하기 어렵다. 그래서 아래 규약을 처음에 고정하고 모든 모델에 똑같이 적용한다.

- **목표값**: 잔여수명을 125 사이클에서 자른다. 초기 구간은 마모가 거의 없어 잔여수명을 구분할 수 없다고 보는 관례를 따른다.

## 5. 모델

### 5.1 전체 구조

```
엔진 센서 14개 + 운전 조건 3개 (사이클마다 1회)
        |
        v
입력 투영 -> 감각 뉴런 (5.2의 대응표)
        |
        v
수컷 CNS 전체: 뉴런 165,122개, 연결 2,454만 개
(배선, 시냅스 수, 흥분/억제 부호는 고정. 사이클마다 1스텝 진행)
        |
        v
하행 뉴런 1,314개 + 운동 뉴런 815개의 활동
        |
        v
출력층 -> 잔여수명
```

### 5.2 센서와 감각 뉴런의 대응

엔진 센서의 물리적 의미에 맞춰 초파리 감각 뉴런을 고른다. **이 대응은 선행 연구에 있는 것이 아니라 이 팀의 설계다.** 그래서 무작위 대응과 비교하는 실험을 함께 한다(6.4).

| 엔진 입력 | 대응 감각 뉴런 | 뉴런 수 |
|---|---|---|
| 온도 3개(T24, T30, T50) | 온도감각 뉴런 | 25 |
| 회전수 4개(Nf, Nc, NRf, NRc) | 고유감각 뉴런(신경삭) | 1,030 |
| 압력 2개(P30, Ps30) | 촉각 기계감각 뉴런(신경삭) | 2,558 |
| 비율, 블리드 5개(phi, BPR, htBleed, W31, W32) | 머리 기계감각 뉴런 | 1,733 |
| 운전 조건 3개(고도, 마하, 스로틀) | 시각 감각 뉴런(비행 환경 맥락) | 4,107 |

### 5.3 두 단계 모델

**M1. 커넥톰 저장소 (중간발표 목표)**

- 가중치와 동역학 값을 모두 고정하고, 출력층만 ridge 회귀로 학습한다.
- spectral radius 0.99 정규화, 누설률 0.9, 입력 배율 0.7은 Costi 등이 쓴 값을 그대로 쓴다. 활성함수는 저장소 모델의 관례대로 tanh로 둔다.
- 엔진 한 대의 전체 기록을 사이클 순서대로 넣으며 상태를 모으고, 각 사이클의 상태로 그 시점의 잔여수명을 맞춘다.
- 역전파가 없어서 가볍다. FD001 학습 엔진 100대를 한꺼번에 돌려도 CPU로 약 10분이다(7장).

**M2. 세포 유형별 값 학습 (최종발표 목표)**

- flyvis(Lappalainen 등, Nature 2024)의 방식을 따른다. flyvis는 연결 구조, 시냅스 수, 부호를 고정하고 세포 유형별 값 734개만 학습했다.
- 이 프로젝트에서는 세포 유형별 시간상수와 휴지 상태(약 2.9만 개), 입력 투영, 출력층을 학습한다. 유형 쌍별 시냅스 강도 배율(385만 개)은 데이터에 비해 너무 많아 기본 설정에서는 뺀다.
- 30사이클 창 단위로 잘라 시간을 거슬러 역전파한다.

동역학 식은 다음과 같다.

```
h_i(t+1) = (1 - 1/τ_k) * h_i(t) + (1/τ_k) * φ( g * Σ_j W_ij h_j(t) + 입력_i(t) + b_k )
W_ij = (뉴런 j의 부호) × (j에서 i로 가는 시냅스 수) / 3,777.6 × 0.99
```

k는 뉴런 i의 세포 유형이다. M1에서는 모든 유형에 1/τ_k = 0.9(누설률), b_k = 0을 똑같이 주고, M2에서 유형별로 학습한다.

## 6. 실험 설계

### 6.1 비교 모델

| 구분 | 모델 | 비고 |
|---|---|---|
| Baseline | LSTM, GRU, 1D-CNN | 학습 파라미터 수를 M2와 맞춘 버전과 문헌 표준 크기 버전을 모두 돌린다 |
| Baseline | 무작위 저장소 | 뉴런 수, 연결 밀도, spectral radius를 커넥톰 저장소와 맞춘다 |
| 참고 수치 | 문헌 값 | FD001 기준 LSTM 계열 RMSE 약 14~16, 최근 혼합 모델 약 12. 규약이 달라 참고로만 쓴다 |

### 6.2 대조군

| 대조군 | 만드는 법 | 확인하는 것 |
|---|---|---|
| 배선 섞기 | 뉴런마다 들어오고 나가는 연결 수는 유지하고 연결 상대만 무작위로 바꿈 | 정확한 배선의 효과와 연결 수 분포의 효과를 분리 |
| 가중치 섞기 | 배선은 유지하고 시냅스 수만 섞음 | Costi 등의 결과(가중치를 섞으면 이점이 사라짐)가 재현되는가 |
| 부호 변경 | 글루탐산을 + 로 둔 버전 | 부호 규칙의 영향 |
| spectral radius | 0.25, 0.5, 0.75, 0.99 | Churchland 등이 지적한 배율 효과 |

### 6.3 데이터 양 실험 (핵심)

- 학습 엔진 수를 10, 25, 50, 100대로 바꾼다. 각 조건에서 엔진을 다르게 뽑아 5번 반복한다.
- 학습 RMSE와 검증 RMSE의 차이를 과적합 격차로 정의하고, 엔진 수에 따른 곡선을 그린다.
- H1이 맞다면 엔진이 적은 쪽에서 커넥톰 저장소와 무작위 저장소의 격차 차이가 가장 커야 한다.

### 6.4 절제와 입출력 실험

| 실험 | 내용 |
|---|---|
| 부위 절제 | 시각엽 내재 뉴런(89,390), 버섯체, 중심복합체, 신경삭을 하나씩 끄고 성능 변화를 본다 |
| 목 절단 | 하행 뉴런 1,314개와 상행 뉴런 1,846개를 끊어 뇌와 몸을 분리한다 |
| 입력 대응 | 5.2의 의미 대응과 무작위 대응을 비교한다 |
| 출력 위치 | 하행+운동 뉴런(기본), 전체 뉴런에서 무작위 2,129개, 버섯체 출력 뉴런 97개 |

감각 뉴런에서 다른 뉴런까지의 연결 단계를 세어 보니, 모든 뉴런이 머리 감각 뉴런에서 4단계 안에 닿았고 운동 뉴런은 대부분 2단계였다. 신경삭에서는 감각 뉴런이 운동 뉴런으로 바로 이어지는 경로도 있다. 신호가 뇌를 거치지 않고 몸 쪽 회로만으로 처리될 수 있다는 뜻이라, 목 절단 실험으로 뇌의 역할을 확인한다.

### 6.5 지표와 통계

| 지표 | 정의 |
|---|---|
| RMSE | 시험 엔진 마지막 사이클의 예측과 정답(125에서 자름) 사이의 평균제곱근오차 |
| NASA 점수 | d = 예측 − 정답일 때, d < 0이면 exp(−d/13) − 1, d ≥ 0이면 exp(d/10) − 1을 엔진마다 더한다. 늦게 예측할수록 벌점이 크다(Saxena 등 2008, a1 = 10, a2 = 13) |
| 과적합 격차 | 검증 RMSE − 학습 RMSE |

- 모든 모델을 시드 5개로 돌려 평균과 표준편차를 보고한다.
- 모델 간 차이는 엔진 단위 쌍체 부트스트랩으로 검정한다.

### 6.6 오류 분석 범주

수명 구간별 오차(초기, 중기, 말기), 늦은 예측과 이른 예측의 비율, 초기 마모가 큰 엔진, 고장 유형(FD003), 운전 조건(FD002, FD004).

## 7. 실행 환경과 비용

개발용 Mac(15코어 CPU, 24GB 메모리)에서 잰 값이다.

| 항목 | 측정값 |
|---|---|
| 가중치 파일 불러오기 최대 메모리 | 5.6GB (Colab 무료 약 12.7GB 안에 들어감) |
| 저장소 1스텝 (엔진 100대 동시, tanh 포함) | 1.711초 |
| 16스텝 순전파+역전파 (배치 32) | 23.6초 |

- **M1**: FD001 학습 엔진 100대를 한꺼번에 넣으면 가장 긴 엔진 기준 362스텝이다. CPU로 약 10분이면 상태 수집이 끝나고, ridge 회귀는 몇 초면 된다. 데이터 양 실험과 대조군을 모두 돌려도 CPU로 감당할 수 있다.
- **M2**: 30사이클 창 하나에 30스텝이라 배치 32 기준 CPU로 약 44초다. FD001의 창은 17,731개인데, 5사이클 간격으로 뽑으면 약 3,500개로 한 epoch에 CPU로 약 80분이 걸린다. Colab 무료 CPU는 2코어라 T4 GPU가 필요하다.
- **T4 GPU 속도는 아직 재지 않았다.** 6주차까지 측정해 M2 계획을 확정한다.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 커넥톰 모델이 LSTM보다 못함 | 핵심 질문을 "적은 데이터에서의 과적합"으로 잡아 두었으므로, 데이터 양 곡선과 대조군으로 이유를 분석해 발표한다 |
| 이점이 배선이 아니라 분포에서 옴 | 배선 섞기, 가중치 섞기, spectral radius 대조군으로 가려서 보고한다. 그 자체가 선행 연구에 보탤 결과다 |
| M2 학습이 T4에서도 느림 | 창 간격을 넓히고, 학습할 유형을 줄이고, 그래도 느리면 M1 중심으로 결과를 정리한다 |
| 순환 동역학 발산 | spectral radius 정규화, 시간상수 하한, 기울기 자르기 |
| 평가 누수 | 엔진 단위 분할과 학습 엔진만으로 계산한 정규화 통계를 코드로 강제한다 |
| FD002, FD004의 복잡도 | FD001과 FD003을 중심으로 하고, 둘은 여유가 있을 때만 진행한다 |

## 11. 먼저 확인할 것

1. 교수님께 이 구성(추천 데이터셋 C-MAPSS와 공개 커넥톰)이 과목 요건에 맞는지 면담 시간에 확인한다.
2. Costi 등의 공개 코드(https://gitlab.com/EuropeanSpaceAgency/fly_connectome)를 받아 저장소 설정을 그대로 재현할 수 있는지 본다.
3. T4 GPU에서 30스텝 순전파+역전파 속도를 잰다.
4. 평가 규약(4.3)을 팀 전체가 합의하고 문서로 고정한다.
